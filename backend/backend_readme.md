# Backend README

This document explains the backend structure and how everything is organized.

---

## Project Structure

```
backend/
├── main.py                 # FastAPI entry point - all endpoints start here
├── .env                    # API keys and secrets (DO NOT COMMIT)
├── requirements.txt        # Python dependencies
├── routers/               # API endpoint organization
├── services/              # External API integrations
└── models/                # Data validation models
```

---

## What Each Folder Does

### `routers/` - Organizes your API endpoints
- Instead of putting ALL endpoints in `main.py`, you split them by feature
- Example: `routers/voice.py` has all voice-related endpoints, `routers/questions.py` has question endpoints
- Keeps code organized as your API grows
- You'll use these later, not now

**Example structure:**
```
routers/
├── __init__.py
├── voice.py        # POST /api/voice-answer
├── questions.py    # GET /api/questions
└── sessions.py     # POST /api/sessions
```

### `services/` - External API integrations and business logic
- `services/openrouter.py` - All code that talks to OpenRouter API (using Gemini model)
- `services/elevenlabs.py` - All code that talks to ElevenLabs API
- `services/supabase.py` - All database operations
- Separates "how to call external APIs" from "what endpoints to expose"
- You'll create these after `main.py` works

**Example:**
```python
# services/openrouter.py
async def evaluate_answer(transcript: str, question: str):
    # Call OpenRouter API with Gemini model
    # Return score and feedback
```

### `models/` - Data validation (Pydantic models)
- Define what your API expects to receive and send back
- Example: "A voice answer request must have audio_bytes and question_id"
- FastAPI automatically validates incoming data against these
- You'll add these when you start building real endpoints

**Example:**
```python
# models/voice.py
class VoiceAnswerRequest(BaseModel):
    question_id: str
    audio_bytes: bytes
    user_id: str
```

## Environment Variables

Create a `.env` file in the backend directory with:

```bash
# Supabase (Database & Auth)
SUPABASE_URL=your_url_here
SUPABASE_KEY=your_key_here

# AI Evaluation (via OpenRouter)
OPENROUTER_API_KEY=your_key_here

# Text-to-Speech
ELEVENLABS_API_KEY=your_key_here
```

**IMPORTANT:** Never commit `.env` to git! It's already in `.gitignore`.

---

## Running the Backend

1. Activate virtual environment:
```bash
cd backend
source venv/bin/activate  # On Mac/Linux
# or
venv\Scripts\activate     # On Windows
```

2. Install dependencies (if not already installed):
```bash
pip install -r requirements.txt
```

3. Run the server:
```bash
uvicorn main:app --reload
```

4. Visit: http://localhost:8000
   - API docs: http://localhost:8000/docs (auto-generated by FastAPI)

## Development Workflow

1. **Start simple** - Get basic FastAPI app running in `main.py`
2. **Add services** - Create OpenRouter (Gemini model) and ElevenLabs integrations
3. **Create routers** - Split endpoints into organized files
4. **Add models** - Define data validation as you build endpoints
5. **Test** - Use FastAPI's auto-generated docs at `/docs` to test endpoints
